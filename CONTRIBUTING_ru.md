# Руководство по контрибьюции в контракты и рецепты NativeBPM

Спасибо за интерес к проекту NativeBPM! В этом репозитории поддерживаются официальные спецификации контрактов OpenAPI 3.0 (`api/openapi.yaml`), схемы JSON Schema (`schema/`) и рецепты интеграции через нативный код (Zero-SDK).

---

## ⚡ Архитектурный принцип: Нативный код (Zero-SDK)

В NativeBPM утвержден **единственный стандарт интеграции: Нативный код (Workflow-as-Code)**.

Интеграция выполняется без сторонних клиентских SDK через:
1. **Нативный AST-парсинг**: Go (`go/parser`), Python (async AST), TypeScript/JavaScript (ECMA-262).
2. **Декларативные State Machines**: JSON, YAML и DMN 1.3 с автоматическим расчетом BPMN.
3. **Wasmee WASM Runtime**: Изолированные воркеры в WebAssembly через Unix Domain Sockets (< 50 мкс).
4. **Стандартный HTTP/UDS**: Вызовы через встроенные стандартные библиотеки (`net/http`, `urllib`, `fetch`, `HttpClient`, `curl`).

Генерация и установка внешних клиентских пакетов больше **не требуется и не поддерживается**.

---

## 🛠️ Порядок внесения изменений

### 1. Изменение спецификации OpenAPI 3.0
* Отредактируйте файл [`api/openapi.yaml`](api/openapi.yaml).
* Соблюдайте стандарт OpenAPI 3.0.3 с явным описанием моделей запросов и ответов.
* Проверьте соответствие спецификациям BPMN 2.0 / DMN 1.3.

### 2. Изменение схем JSON Schema
* Редактируйте схемы в папке [`schema/`](schema/).
* Обеспечьте совместимость со стандартом JSON Schema Draft 2020-12.

### 3. Добавление рецептов интеграции
* Новые примеры для различных языков добавляются в [Zero-SDK Cookbook](https://gitlab.com/nativebpm/docs/-/blob/main/nativebpm/NB-284/zero_sdk_cookbook_ru.md).
* Все примеры должны использовать **исключительно встроенные стандартные библиотеки** без внешних пакетов.
